# Ciao, Web! v23 — Standalone Application Design

Дата: 2026-09-06
Статус: дизайн утверждён в чате, ожидает финального просмотра файла перед планом реализации
Ветка: `v23-test`

## 1. Цель

Переписать Ciao, Web! v23 как самостоятельное Telegram Mini App, а не как модификацию v22.5.

Текущая экспериментальная v23 построена поверх HTML v22.5 и legacy DOM. Этот подход прекращается. Новая v23 должна иметь собственный frontend, собственный app shell, собственную навигацию и единый backend-контракт.

Production v22.5 остаётся нетронутой до отдельного подтверждённого релиза v23.

## 2. Что сохраняем из текущего TEST-контура

Сохраняются только инфраструктурные части, которые уже изолированы от production:

- Cloudflare Worker `ciao-web-v23-test`;
- отдельный Supabase TEST project;
- TEST backend с публичной точкой входа `ciao-v23-api`;
- персональная скрытая TEST-кнопка Telegram;
- TEST whitelist;
- CI/CD для TEST-ветки.

Существующий frontend текущей v23 не является базой для нового приложения.

## 3. Жёсткие архитектурные запреты

В новой v23 запрещено:

- загружать, копировать или встраивать `v22-5.html`;
- использовать `legacy-surface-adapter`;
- инжектить новый UI в DOM старого приложения;
- иметь два конкурирующих router/state/DOM owner;
- проксировать запросы через старую цепочку `v6 -> v5 -> v4 -> core`;
- держать отдельную frontend-логику для Serie A и еврокубков;
- использовать production Supabase в TEST;
- переносить TEST-базу поверх production;
- выполнять destructive migrations production-базы до подтверждённой стабильности v23.

## 4. Целевая архитектура

### TEST

`Telegram -> ciao-web-v23-test -> ciao-v23-api -> TEST Supabase`

### Production после отдельного релиза

`Telegram -> production v23 frontend -> production ciao-v23-api -> существующая production Supabase`

Frontend и backend используют одинаковый контракт в TEST и production. Различаются только environment/configuration и база данных.

## 5. Frontend

Новый frontend создаётся с нуля и имеет:

- собственный `index.html`;
- один app shell;
- один router;
- одно хранилище состояния;
- один Telegram init;
- один API client;
- один live/polling controller;
- независимые экраны;
- переиспользуемые UI-компоненты.

Основные общие компоненты:

- Bottom Navigation;
- Match Card;
- Team Badge;
- Tournament Card;
- Profile Summary;
- Loading Skeleton;
- Inline Error State;
- Empty State;
- Match Center header/tabs.

Каждый крупный модуль должен иметь одну понятную ответственность и не зависеть от DOM другого экрана.

## 6. Визуальное направление

Используется фирменный тёмно-синий стиль Ciao, Web!, но интерфейс рисуется заново.

Принципы:

- глубокий тёмно-синий фон;
- карточки на 1–2 тона светлее основного фона;
- белый основной текст;
- синие/голубые активные состояния;
- мягкие скругления;
- минимальные бордеры;
- минимум визуального шума;
- крупные ключевые числа и действия;
- единая система размеров, отступов, карточек и состояний.

Новая v23 не обязана визуально копировать карточки v22.5.

## 7. Основная навигация

Нижнее меню содержит ровно пять разделов:

1. Главная
2. Прогнозы
3. Рейтинг
4. Матчи
5. Таблицы

Текст подписей всегда видим.

Пример route-модели:

- `/home`
- `/predictions`
- `/predictions/mine`
- `/ranking/all`
- `/ranking/italy`
- `/ranking/europe`
- `/matches/serie-a`
- `/matches/coppa-italia`
- `/matches/ucl`
- `/matches/uel`
- `/matches/uecl`
- `/match/:competition/:matchId/:section`
- `/tables/serie-a`
- `/tables/ucl`
- `/tables/uel`
- `/tables/uecl`

Router хранит history Mini App. Back должен восстанавливать предыдущий экран, subview, tournament, filters и scroll.

Telegram Back Button и browser/system Back используют одну и ту же навигационную модель.

Каждый основной раздел запоминает своё последнее состояние.

## 8. Главная

Главная — компактный обзор, а не копия всех разделов.

Содержит:

- шапку Ciao, Web!;
- аватар пользователя;
- компактный профиль;
- очки;
- место в рейтинге;
- точные счета;
- любимый клуб;
- ближайший матч любимого клуба;
- блок «Кальчо сегодня»;
- live-матчи, если они идут.

Прогнозы на Главной не показываются.

### Любимый клуб

Пользователь выбирает один любимый итальянский клуб.

Карточка любимого клуба показывает ближайший матч среди всех поддерживаемых соревнований. Вся карточка матча открывает Match Center.

Если клуб не выбран, показывается явное действие выбора клуба.

### Кальчо сегодня

Показываются матчи текущего локального дня пользователя, в которых участвует клуб Серии А, включая допустимые матчи Кубка Италии и еврокубков.

Если матчей нет, точный текст:

`Кальчо сегодня нет :(`

Live-матчи сортируются выше обычных сегодняшних матчей.

## 9. Поддерживаемые соревнования

Внутренние стабильные ID:

- `serie_a`
- `coppa_italia`
- `ucl`
- `uel`
- `uecl`

Пользовательские названия только на русском:

- Серия А
- Кубок Италии
- Лига чемпионов
- Лига Европы
- Лига конференций

Технические ID никогда не отображаются в UI.

## 10. Ключевое правило еврокубков

Для Лиги чемпионов, Лиги Европы и Лиги конференций приложение учитывает только матчи, где хотя бы один участник — итальянский клуб.

Это правило применяется на backend-уровне и обязательно действует для:

- Матчей;
- Прогнозов;
- Моих прогнозов;
- Кальчо сегодня;
- ближайшего матча любимого клуба;
- Match Center;
- live-обновлений;
- рейтинга «Еврокубки»;
- общего рейтинга в еврокубковой части.

Квалификационные и предварительные раунды еврокубков исключаются полностью.

Frontend не определяет самостоятельно, является ли матч «итальянским». Backend отдаёт только допустимые матчевые сущности.

Итальянская принадлежность определяется по стабильному `team_id` и нормализованному клубному справочнику/стране, а не по названию строки.

API должен отклонять попытку сохранить прогноз на недопустимый еврокубковый матч даже при ручном запросе.

## 11. Прогнозы

Раздел содержит две вкладки:

- Прогнозы
- Мои прогнозы

Фильтр соревнований:

- Все
- Серия А
- Кубок Италии
- Лига чемпионов
- Лига Европы
- Лига конференций

### Прогнозы

Показываются только матчи, на которые прогноз ещё открыт.

Правила:

- дедлайн: за 15 минут до kickoff;
- до дедлайна прогноз можно создавать и изменять;
- после дедлайна изменение запрещено;
- сохранённый прогноз немедленно отображается в карточке;
- сохранение подтверждается inline-состоянием, без системного popup;
- еврокубки содержат только допустимые матчи итальянских клубов;
- квалификации отсутствуют.

### Мои прогнозы

Для каждого прогноза показываются:

- турнир;
- команды;
- локальное время;
- поставленный счёт;
- фактический счёт после завершения;
- начисленные очки;
- статус матча.

До дедлайна пользователь может вернуться к прогнозу и изменить его.

## 12. Система начисления очков

Единая система для всех поддерживаемых турниров:

- 5 — точный счёт;
- 3 — точная разница мячей при правильном исходе;
- 2 — правильный исход;
- 0 — промах.

Дедлайн всегда равен `kickoff UTC - 15 минут`.

Frontend не пересчитывает очки и не определяет дедлайн самостоятельно как источник истины.

## 13. Рейтинг

Три scope:

- Все
- Италия
- Еврокубки

Состав:

- `Все` = Серия А + Кубок Италии + допустимые матчи UCL/UEL/UECL;
- `Италия` = Серия А + Кубок Италии;
- `Еврокубки` = только допустимые матчи итальянских клубов в UCL/UEL/UECL.

Backend возвращает уже рассчитанную таблицу рейтинга для выбранного scope.

## 14. Матчи

Стартовый экран содержит пять крупных карточек турниров:

- Серия А
- Кубок Италии
- Лига чемпионов
- Лига Европы
- Лига конференций

### Серия А

Матчи группируются по турам и статусам.

### Кубок Италии

Отображение начинается с 1/8 финала. Более ранние стадии не показываются.

### Еврокубки

Показываются только допустимые матчи итальянских клубов. Квалификации отсутствуют.

Вся карточка матча открывает единый Match Center.

## 15. Match Center

Match Center — отдельный полноценный экран, общий для всех соревнований.

Вкладок ровно пять:

1. Обзор
2. Статистика
3. События
4. Составы
5. Игроки

### Обзор

Может содержать:

- статус;
- дату и локальное время;
- стадион;
- тур/стадию;
- текущий или итоговый счёт.

### Статистика

Отображаются только реально полученные показатели. Отсутствующее значение не подменяется нулём.

### События

Поддерживаются доступные у провайдера:

- голы;
- автоголы;
- пенальти;
- жёлтые/красные карточки;
- замены;
- VAR.

### Составы

- стартовые 11;
- схема;
- запасные;
- тренер, если доступен.

### Игроки

Показывается статистика игроков конкретного матча, если она есть у провайдера.

Match Center не имеет отдельной Serie A-реализации.

## 16. Таблицы

Раздел содержит:

- Серия А
- Лига чемпионов
- Лига Европы
- Лига конференций

Кубка Италии в разделе «Таблицы» нет.

Все названия команд и турниров в таблицах отображаются на русском языке.

## 17. Единая модель футбольных данных

Backend нормализует данные внешнего провайдера до единой модели Match.

Минимальные поля:

- `competition`
- `provider_match_id`
- `season`
- `stage`
- `round`
- `kickoff_at`
- `status`
- `home_team`
- `away_team`
- `score`
- `is_italian_relevant`
- `is_qualification`

Один и тот же нормализованный матч используется всеми экранами.

Предпочтительный единый формат прогноза:

- `user_id`
- `match_id`
- `home_score`
- `away_score`
- `points`
- `created_at`
- `updated_at`
- `locked_at`

Переход production-базы к единой модели выполняется только совместимыми migrations без потери существующих прогнозов.

## 18. Backend

Frontend общается только с одним публичным backend-контрактом `ciao-v23-api`.

Backend отвечает за:

- проверку Telegram initData;
- проверку доступа/подписки;
- синхронизацию профиля;
- нормализацию BSD;
- русские canonical names;
- фильтр итальянских клубов в еврокубках;
- исключение квалификаций;
- дедлайны;
- сохранение прогнозов;
- начисление баллов;
- ranking scopes;
- live data;
- Match Center;
- настройки пользователя.

Старые legacy API-цепочки не являются частью архитектуры v23.

## 19. Русская локализация

В пользовательском интерфейсе все названия команд, турниров и стадий должны быть на русском языке.

Примеры canonical names:

- Inter -> Интер
- Juventus -> Ювентус
- Bayern München -> Бавария
- Paris Saint-Germain -> ПСЖ
- Manchester City -> Манчестер Сити

Примеры стадий:

- Round of 16 -> 1/8 финала
- Quarter-finals -> 1/4 финала
- Semi-finals -> 1/2 финала
- Final -> Финал
- League phase -> Общий этап

Русское название должно определяться централизованно, по стабильному идентификатору, а не переводиться отдельно в компонентах.

## 20. Склонения и грамматика

В v23 создаётся единый localization/grammar layer.

Он отвечает за:

- числительные;
- формы существительных;
- падежные формы турнирных названий;
- падежные формы клубов там, где они нужны;
- даты;
- системные тексты;
- тексты уведомлений.

Обязательные примеры:

- 1 очко / 2 очка / 5 очков;
- 1 матч / 3 матча / 10 матчей;
- 1 прогноз / 2 прогноза / 7 прогнозов;
- 1 гол / 4 гола / 11 голов;
- в Серии А;
- в Кубке Италии;
- в Лиге чемпионов;
- матч Лиги Европы.

Запрещено собирать грамматически зависимые фразы простой конкатенацией строк.

Для клубов допускается словарь падежных форм. Для неоднозначных или несклоняемых названий используется безопасная формулировка интерфейса.

Автотесты обязательно проверяют формы для чисел:

`1, 2, 5, 11, 21, 22, 25`.

## 21. Время и часовой пояс

В базе и API kickoff хранится как абсолютное UTC-время.

Frontend отображает время в локальном timezone пользователя/устройства.

Интерфейс использует `ru-RU` и локальные формы вроде:

- Сегодня · 21:45
- Завтра · 19:30
- 12 сентября · 21:45

При смене timezone устройства отображение меняется автоматически.

Дедлайн не зависит от локального отображения и всегда считается от абсолютного kickoff.

## 22. Профиль пользователя

Из Telegram синхронизируются:

- first name;
- last name;
- username;
- avatar, если доступен.

Telegram ID остаётся неизменяемой пользовательской идентичностью.

При изменении имени или username в Telegram mutable profile fields обновляются при следующем входе.

## 23. Любимый клуб

Пользователь выбирает один любимый итальянский клуб.

Выбор используется для:

- Главной;
- ближайшего матча;
- Кальчо сегодня;
- быстрых переходов в Match Center;
- уведомлений.

В selector показываются логотип и русское название клуба. Поиск работает по русскому названию.

## 24. Настройки

Минимальные настройки v23:

### Уведомления

- дедлайн прогнозов;
- составы;
- начало матча;
- результат матча.

### Приложение

- любимый клуб;
- timezone — автоматически;
- язык интерфейса — русский.

Ручной timezone override не входит в первую версию.

## 25. Уведомления

Уведомления — backend-задача и не зависят от того, открыт ли Mini App.

Еврокубковые уведомления отправляются только по допустимым матчам итальянских клубов.

Все тексты уведомлений проходят через тот же localization/grammar layer.

## 26. Live updates

У приложения один владелец polling.

Правила:

- live-счёт, минута, события и доступная статистика обновляются без полной перерисовки приложения;
- Match Center может обновляться чаще, когда открыт live-матч;
- при уходе с live-экрана лишние запросы прекращаются;
- разные компоненты не создают независимые polling loops.

## 27. Ошибки и last-good-data

Каждый крупный блок изолирован по ошибкам.

Если один источник временно недоступен:

- навигация продолжает работать;
- другие блоки не ломаются;
- последние успешные данные не заменяются пустой ошибкой;
- рядом показывается компактный статус `Не удалось обновить`;
- пользователь может повторить запрос.

Полноценный offline-mode не является целью первой версии. Используется last-good-data cache текущей сессии.

Не показывать пользователю технические сообщения вида `api_error` как основной UI.

## 28. Производительность

Каждый экран загружает только необходимые данные.

Примеры:

- Главная не загружает полные составы всех матчей;
- вкладка «Статистика» Match Center загружается при открытии;
- вкладки «Составы», «События», «Игроки» загружаются по потребности;
- один live controller не дублирует запросы.

## 29. Production data safety

Production Supabase не пересоздаётся и не перезаписывается.

При релизе v23:

- frontend заменяется отдельно;
- новый backend-код разворачивается отдельно;
- schema changes применяются migrations;
- существующие пользователи сохраняются;
- Telegram ID сохраняются;
- существующие прогнозы и очки сохраняются;
- пользовательские настройки сохраняются;
- TEST-данные не переносятся в production.

До подтверждённой стабильности v23 запрещены destructive migrations, удаляющие старые таблицы/колонки/данные, нужные v22.5.

## 30. Rollback

До отдельного подтверждения стабильности v23 production должна сохранять возможность вернуть frontend v22.5.

Миграции v23 должны быть совместимы с этой стратегией отката.

Переход на v23 не является точкой невозврата.

## 31. TEST isolation

TEST использует только:

- `ciao-web-v23-test`;
- TEST Supabase;
- TEST `ciao-v23-api`;
- персональную Telegram TEST-кнопку;
- TEST whitelist.

TEST build должен автоматически падать, если содержит production Supabase reference.

## 32. Автоматическое тестирование

Минимальный обязательный набор включает проверки:

- frontend не загружает и не импортирует legacy v22.5;
- приложение стартует из собственного `index.html`;
- существует один router owner;
- существует один polling owner;
- все пять основных разделов доступны;
- Back восстанавливает экран/subview/tournament/scroll;
- Telegram Back и browser Back эквивалентны;
- Match Center содержит ровно пять вкладок;
- еврокубковые матчи без итальянского клуба исключаются;
- матч итальянского клуба дома включается;
- матч итальянского клуба в гостях включается;
- квалификационный матч итальянского клуба исключается;
- API отклоняет прогноз на недопустимый еврокубковый матч;
- рейтинг «Еврокубки» считает только допустимые матчи;
- Кубок Италии начинается с 1/8 финала;
- Кубка Италии нет в разделе «Таблицы»;
- дедлайн равен kickoff - 15 минут;
- система очков = 5/3/2/0;
- kickoff локализуется для timezone пользователя;
- все пользовательские названия турниров русские;
- canonical club names русские;
- grammar cases тестируются на 1/2/5/11/21/22/25;
- mutable Telegram profile fields синхронизируются;
- Telegram ID не меняется;
- last-good-data сохраняется при refresh failure;
- TEST не содержит production Supabase references;
- production migrations не удаляют существующие пользовательские данные.

## 33. Реальный Telegram smoke-test

Перед production-релизом обязательна проверка через персональную скрытую TEST-кнопку на реальном Telegram WebView.

Smoke-test включает минимум:

- запуск приложения;
- переход по всем пяти разделам;
- прогноз и его изменение до дедлайна;
- «Мои прогнозы»;
- рейтинг всех трёх scope;
- список матчей каждого турнира;
- Match Center и все пять вкладок;
- Back из разных точек входа;
- любимый клуб;
- Кальчо сегодня;
- локальное время;
- русский язык и склонения;
- live-состояние, если доступно;
- временную ошибку/повторный запрос.

## 34. Release gate

Зелёный CI сам по себе не разрешает production deploy.

Production promotion возможен только после одновременного выполнения всех условий:

1. все обязательные автоматические тесты зелёные;
2. TEST build/deploy зелёный;
3. реальный Telegram smoke-test пройден;
4. production migration review подтверждает отсутствие потери данных;
5. rollback на v22.5 остаётся доступным;
6. пользователь даёт явное подтверждение на production release.

## 35. Definition of Done

Новая v23 считается готовой к обсуждению production-релиза только когда:

- это самостоятельное приложение, не основанное на v22.5 HTML/DOM;
- frontend и backend имеют один понятный контракт;
- в еврокубках нет матчей без итальянских клубов;
- квалификации еврокубков отсутствуют;
- все клубы, турниры, стадии и системные тексты отображаются на русском;
- склонения и числительные корректны;
- время локализовано по timezone пользователя;
- дедлайн и scoring остаются 15 минут и 5/3/2/0;
- Back работает предсказуемо из любого экрана;
- Match Center единый;
- ошибки не уничтожают последние корректные данные;
- production data migration безопасна;
- v22.5 остаётся rollback-вариантом до отдельного подтверждения стабильности.
