# Ciao, Web! v23 — Evolution from stable v22.5

Дата: 2026-09-07  
Статус: дизайн согласован по разделам в чате; ожидает финального подтверждения этого файла перед implementation plan  
Ветка: `v23-evolution-test`  
База ветки: стабильный production baseline `0dc28fa382d7bbdafdd428616afb310cbfcbcb30`

## 1. Цель

Развивать Ciao, Web! v23 как эволюцию стабильной v22.5, а не как отдельное standalone-приложение.

v22.5 остаётся единственным владельцем интерфейса, DOM, навигации, состояния и визуального языка. Новые функции должны выглядеть и вести себя так, будто они всегда были частью v22.5.

Production v22.5 не изменяется до отдельного подтверждённого релиза.

## 2. Что прекращаем

Не продолжаем standalone-v23 как frontend-направление.

В финальную архитектуру не входят:

- отдельный `src/v23` app shell;
- второй router;
- второй state owner;
- отдельный standalone bottom navigation;
- отдельный standalone CSS/design system;
- overlay поверх v22.5;
- `legacy-surface-adapter`;
- инъекция второго приложения в DOM v22.5;
- параллельное владение одним и тем же экраном двумя runtime.

Текущая standalone-ветка может сохраняться в истории только как источник отдельных полезных backend/domain-решений.

## 3. Базовый принцип интерфейса

Внешний вид v22.5 сохраняется максимально близко к 1:1.

Сохраняем:

- существующую шапку;
- текущую нижнюю навигацию как основу;
- размеры и характер карточек;
- существующую типографику;
- отступы, радиусы и цветовую систему;
- привычную логику экранов.

Новые элементы стилизуются под v22.5, а не наоборот.

Первый релиз новой v23 не включает отдельный визуальный redesign. Возможный facelift обсуждается только после функциональной стабильности.

## 4. Целевая архитектура

### TEST

`Telegram -> ciao-web-v23-test -> frontend на базе v22.5 -> ciao-v23-api -> TEST Supabase`

### Production после отдельного релиза

`Telegram -> production frontend на базе v22.5 -> production ciao-v23-api -> существующая production Supabase`

Скрытая кнопка Telegram `🧪 Ciao v23 TEST` остаётся единой точкой реального smoke-test новой версии.

## 5. Один frontend owner

v22.5 остаётся единственным frontend runtime.

Запрещено добавлять поверх него второй app shell/router/state owner.

Новые экраны и состояния добавляются внутрь существующих механизмов v22.5:

- существующая Главная расширяется;
- существующее нижнее меню дорабатывается;
- существующий экранный renderer расширяется;
- Match Center становится частью той же навигационной модели;
- Back работает через один общий механизм;
- live/polling имеет одного владельца.

Никаких глобальных `innerHTML`-замен общего root ради новой функции.

## 6. Единая BSD-интеграция

В приложении должен быть один общий BSD provider/data layer.

Все пять турниров используют одну нормализацию матчей, команд, сезонов, стадий и статусов:

- Серия А;
- Кубок Италии;
- Лига чемпионов;
- Лига Европы;
- Лига конференций.

BSD является единым источником матчевых данных для:

- Матчей;
- Прогнозов;
- Кальчо сегодня;
- ближайшего матча любимого клуба;
- Match Center;
- live;
- таблиц;
- расчёта результатов прогнозов.

Не создаются отдельные BSD-клиенты или параллельные модели данных для Серии А и еврокубков.

## 7. Единая база пользователей

`cp_users` — единственная таблица прогнозистов.

У пользователя один аккаунт для всех турниров, один профиль, один рейтинг, одна история прогнозов, один любимый клуб и один набор настроек.

### 7.1. Идентичность пользователя

Пользователь определяется только по стабильному `Telegram ID`, полученному из валидированного Telegram `initData`.

Имя, фамилия и `@username` не используются как ключ доступа.

При каждом запуске:

1. валидируется `initData`;
2. извлекается `telegram_id`;
3. по нему находится существующий `cp_users`;
4. пользователь допускается в тот же аккаунт;
5. изменяемые Telegram-поля синхронизируются свежими значениями.

Пользователь должен продолжать входить в приложение, если он:

- изменил имя;
- изменил фамилию;
- изменил `@username`;
- удалил username.

`telegram_id` никогда не меняется и не перезаписывается по имени/username.

Все существующие прогнозы, очки, любимый клуб и настройки сохраняются за тем же Telegram ID.

Обязателен регрессионный тест: тот же Telegram ID + полностью изменённые имя/username = тот же пользователь и та же история.

## 8. Единая база прогнозов

`cp_predictions` — единственная финальная таблица прогнозов для всех пяти турниров.

Не используется отдельная финальная таблица прогнозов для еврокубков.

Существующая `cp_predictions` расширяется только безопасными additive migrations. Минимальная универсальная модель должна включать:

- `user_id`;
- `competition`;
- стабильный `provider_match_id` BSD;
- при необходимости локальный `match_id`/связь с `cp_matches`;
- `home_score`;
- `away_score`;
- фактический результат/служебные поля результата;
- `points`;
- `created_at`;
- `updated_at`;
- lock/deadline metadata, если это требуется текущей схеме.

Старые прогнозы Серии А не теряются и получают/трактуются как `competition = serie_a`.

Новые прогнозы Кубка Италии, ЛЧ, ЛЕ и ЛК записываются туда же.

Рейтинг и пользовательская статистика считаются из одной общей истории прогнозов.

## 9. Система прогнозов

Система начисления не меняется:

- 5 очков — точный счёт;
- 3 очка — точная разница мячей при правильном исходе;
- 2 очка — правильный исход;
- 0 очков — промах.

Дедлайн: ровно за 15 минут до абсолютного kickoff.

Frontend не является источником истины для scoring/deadline.

## 10. Турниры и фильтрация

Поддерживаются:

- `serie_a` — Серия А;
- `coppa_italia` — Кубок Италии;
- `ucl` — Лига чемпионов;
- `uel` — Лига Европы;
- `uecl` — Лига конференций.

Кубок Италии в пользовательском продукте начинается с 1/8 финала.

В еврокубках учитываются и отображаются только матчи, где участвует хотя бы один итальянский клуб.

Квалификационные/предварительные раунды исключаются.

Это правило применяется к:

- Матчам;
- Прогнозам;
- Моим прогнозам;
- Кальчо сегодня;
- любимому клубу;
- Match Center;
- live;
- рейтингу.

Исключение: общие таблицы ЛЧ/ЛЕ/ЛК остаются полными и содержат все клубы соревнования.

## 11. Русская локализация

Все видимые названия турниров, команд и стадий — на русском.

Не допускается английский fallback в пользовательском UI.

Время матчей хранится/передаётся как UTC timestamp, но показывается в timezone устройства пользователя.

Используются корректные русские формы:

- 1 очко / 2 очка / 5 очков;
- 1 матч / 3 матча / 10 матчей;
- 1 прогноз / 2 прогноза / 7 прогнозов;
- корректные падежи названий турниров и клубов там, где они нужны.

Ошибка локализации одного нового матча не должна обрушать всё приложение или весь основной root. Ошибка локализуется до конкретного блока/списка.

## 12. Новые функции внутри v22.5

### Главная

Сохраняется существующая Главная v22.5 и дополняется:

- любимым клубом;
- ближайшим матчем любимого клуба;
- блоком `Кальчо сегодня`;
- live-данными в существующем визуальном языке.

### Прогнозы

Раздел развивается внутри v22.5:

- `Прогнозы`;
- `Мои прогнозы`;
- фильтры всех пяти турниров.

### Рейтинг

Scopes:

- Все;
- Италия;
- Еврокубки.

`Италия` = Серия А + Кубок Италии.  
`Еврокубки` = допустимые матчи ЛЧ/ЛЕ/ЛК с итальянскими клубами.

### Матчи

Пять турниров внутри существующего интерфейса v22.5.

### Match Center

Один общий Match Center для всех турниров:

- Обзор;
- Статистика;
- События;
- Составы;
- Игроки.

### Таблицы

- Серия А;
- Лига чемпионов;
- Лига Европы;
- Лига конференций.

Кубка Италии в `Таблицах` нет.

## 13. Ошибки и деградация

Ключевое правило: новая функция не имеет права ломать старую стабильную часть v22.5.

Примеры:

- недоступен API еврокубков -> Серия А и старая Главная продолжают работать;
- не загрузился Match Center -> раздел Матчи остаётся доступен;
- отсутствует локализация одного матча -> не показывается глобальный fatal screen;
- временная ошибка live -> сохраняются последние корректные данные;
- новый API недоступен -> не уничтожается существующий root/DOM v22.5.

## 14. TEST и production

Новая ветка разработки: `v23-evolution-test`.

Она создана непосредственно от стабильного baseline `0dc28fa382d7bbdafdd428616afb310cbfcbcb30`.

TEST использует:

- `ciao-web-v23-test`;
- TEST Supabase;
- TEST `ciao-v23-api`;
- существующую скрытую Telegram кнопку.

Production не изменяется до отдельного явного решения пользователя.

Production DB остаётся источником существующих пользователей и прогнозов при будущем релизе.

Миграции production должны быть additive и backward-safe. Никакой замены production DB тестовой базой.

## 15. Порядок реализации

1. Развернуть чистую v22.5 в TEST и убедиться, что она визуально/функционально соответствует стабильной production.
2. Подключить единый BSD/data adapter и новый API без изменения внешнего интерфейса.
3. Унифицировать `cp_predictions` для всех турниров безопасной миграцией.
4. Проверить Telegram-ID login/sync при изменённом имени и username.
5. Главная: любимый клуб + Кальчо сегодня.
6. Прогнозы + Мои прогнозы + пять турниров.
7. Рейтинг: Все / Италия / Еврокубки.
8. Матчи: пять турниров.
9. Единый Match Center.
10. Таблицы: Серия А + полные ЛЧ/ЛЕ/ЛК.
11. Back/live/local timezone/regression smoke.
12. Полный реальный Telegram smoke через `🧪 Ciao v23 TEST`.
13. Только после отдельного подтверждения — production release plan.

После каждого крупного этапа TEST должен оставаться пригодным для ручной проверки в Telegram.

## 16. Критерии готовности

Версия не считается готовой, пока одновременно не выполнено следующее:

- интерфейс остаётся визуально узнаваемой v22.5;
- нет второго frontend runtime/overlay;
- BSD integration единая;
- `cp_users` единая;
- `cp_predictions` единая для всех пяти турниров;
- изменение Telegram имени/username не создаёт нового пользователя и не блокирует вход;
- старые прогнозы Серии А сохранены;
- scoring 5/3/2/0 не изменён;
- дедлайн -15 минут не изменён;
- еврокубки содержат только матчи с итальянскими клубами;
- таблицы еврокубков полные;
- русская локализация не пропускает видимые английские названия;
- локальное время отображается по timezone устройства;
- ошибка новой функции не ломает старую часть приложения;
- Back и live проверены в Telegram WebView;
- production не изменён без отдельного подтверждения.
