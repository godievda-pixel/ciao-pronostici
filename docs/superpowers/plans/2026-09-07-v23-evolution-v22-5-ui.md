# Ciao, Web! v23 Evolution on v22.5 UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Добавить новые функции v23 прямо внутрь стабильного интерфейса v22.5, сохранив его внешний вид, один DOM/navigation owner и привычное поведение.

**Architecture:** `v22-5-evolution.html` остаётся главным и единственным runtime. Новые JS-файлы под `src/evolution/` являются только библиотеками/рендерами, вызываемыми существующим runtime v22.5; они не создают второй app shell, router, bottom nav или глобальный render loop. Все новые данные идут через единый `ciao-v23-api`, но ошибка нового API локализуется до конкретного нового блока и не уничтожает старую часть v22.5.

**Tech Stack:** существующий v22.5 HTML/CSS/JS, browser classic scripts/ES-compatible helpers, Telegram WebApp API, `ciao-v23-api`, Node.js 22 built-in tests, Cloudflare Static Assets.

**Spec:** `docs/superpowers/specs/2026-09-07-v23-evolution-from-v22-5-design.md`

**Prerequisite:** `docs/superpowers/plans/2026-09-07-v23-evolution-foundation-data.md` полностью GREEN и вручную принят через `🧪 Ciao v23 TEST`.

## Global Constraints

- Не менять визуальный язык v22.5 ради новых функций.
- Не создавать второй app shell/router/state owner/bottom navigation.
- Не использовать `legacy-surface-adapter`, modular overlay или замену общего root новой программой.
- Существующие рабочие части v22.5 продолжают работать при сбое нового API.
- Новые элементы выглядят как часть v22.5: те же шрифты, размеры, радиусы, цвета, spacing и карточки.
- Home не показывает прогнозы.
- Bottom nav в итоге: `Главная · Прогнозы · Рейтинг · Матчи · Таблицы`, но реализуется как эволюция существующей nav v22.5.
- Все новые team/tournament/stage names только по-русски.
- Время показывается в timezone устройства; deadline остаётся абсолютным backend deadline.
- Еврокубковые match entities только с итальянскими клубами; qualification отсутствуют.
- UCL/UEL/UECL standings полные.
- После каждого Task нужен реальный Telegram smoke соответствующего пути.

- `cloudflare-production/src/v22-5-evolution.html` — существующий runtime v22.5, который вызывает новые helpers и по-прежнему владеет navigation/root.
- `cloudflare-production/src/evolution/api-client.js` — единственный frontend client для новых `ciao-v23-api` actions.
- `cloudflare-production/src/evolution/formatters.js` — timezone/русские числа/безопасный text formatting.
- `cloudflare-production/src/evolution/match-view.js` — чистый renderer match cards в стиле v22.5; не делает fetch/navigation.
- `cloudflare-production/src/evolution/home.js` — favorite + Calcio Today render/model helpers.
- `cloudflare-production/src/evolution/predictions.js` — tournament filters, My Predictions, save states.
- `cloudflare-production/src/evolution/ranking.js` — scopes `all/italy/europe`.
- `cloudflare-production/src/evolution/matches.js` — tournament chooser + lists/grouping.
- `cloudflare-production/src/evolution/match-center.js` — 5 sections, render-only controller integrated into v22.5 screen lifecycle.
- `cloudflare-production/src/evolution/tables.js` — standings tournament switch/render.
- `cloudflare-production/src/evolution/live-controller.js` — один owner нового live polling, lifecycle-controlled by v22.5.
- `cloudflare-production/test/evolution-ui-*.test.mjs` — static/pure-function regression tests.

Every helper uses the namespace:

```js
window.CiaoEvolution = window.CiaoEvolution || {};
```

but must not automatically render anything on load.

Forbidden in helper files:

```text
history.pushState
history.replaceState
window.onpopstate
Telegram.WebApp.BackButton.onClick
creation/replacement of bottom navigation
replacement of #ciao-miniapp-root innerHTML
standalone DOMContentLoaded app bootstrap
```

Those remain owned by the existing v22.5 runtime.

- [ ] **Step 3: Implement the client**

```js
function createEvolutionApi({ baseUrl, getInitData, fetchImpl = fetch }) {
  return {
    async call(action, payload = {}) {
      const response = await fetchImpl(baseUrl, {
        method: 'POST',
        headers: {
          'content-type': 'application/json',
          'x-telegram-init-data': getInitData() || '',
        },
        body: JSON.stringify({ action, ...payload }),
      });
      const json = await response.json().catch(() => ({}));
      if (!response.ok || json?.ok === false) {
        const error = new Error(json?.error || `api_http_${response.status}`);
        error.code = json?.error || `api_http_${response.status}`;
        throw error;
      }
      return json.data ?? json;
    },
  };
}
```

- [ ] **Step 4: Implement Russian/device-time formatters**

```js
function pluralRu(value, forms) {
  const n = Math.abs(Number(value));
  const n10 = n % 10;
  const n100 = n % 100;
  if (n10 === 1 && n100 !== 11) return forms[0];
  if (n10 >= 2 && n10 <= 4 && !(n100 >= 12 && n100 <= 14)) return forms[1];
  return forms[2];
}

function points(value) {
  return `${value} ${pluralRu(value, ['очко','очка','очков'])}`;
}

function localDateTime(utcIso) {
  return new Intl.DateTimeFormat('ru-RU', {
    day: 'numeric', month: 'long', hour: '2-digit', minute: '2-digit',
  }).format(new Date(utcIso));
}
```

No manual Moscow timezone.
